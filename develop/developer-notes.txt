Strategy behaviour
    src/tests/strategy/behaviour.js measures how the ghosts press Pac-Man. Finding: two thirds of normal ghost decisions have the same value for every legal move (ghosts away from his frontier see no gradient), so only the ghost already on the frontier takes territory and the rest wander; the joint action never beats the best single-ghost move. The direction-aware domain seed (below) removed the blind decisions: 67% -> 0%.
    Domain seed
        A moving character seeds only its destination cell, at (1 - progress) / speed; the origin is not seeded because the wave reaches it back from the destination. The duplicate check uses the direction the wave comes from, not the seed direction. The old seed spread from the origin in every direction, so a ghost moving away from a door still owned it. Effects: the circuit battery went from 9/9 escapes to 1/9 (cover 13% -> 15%), the trap still catches 20/20, and the blind ghost decisions went from 67% to 0%. The nine unowned cells in the classic domain are the enclosed house/tunnel area and appear with progress 0 too (pre-existing, not caused by the seed). The ghost domain is smaller while moving, so the territory weights may need rebalancing.
    Heuristic
        evaluateSearchState is SEARCH_VALUE_LIVES * (1 - lives/initialLives) + SEARCH_VALUE_CONTROL * (1 - control) + SEARCH_VALUE_DANGER * danger - SEARCH_VALUE_PROGRESS * progress - SEARCH_VALUE_PREY * prey, every term a fraction in [0,1]. progress is eaten/initial pellets; control is the share of the remaining pellets Pac-Man reaches before any ghost, weighted by 1/(1+wait); danger and prey are the closeness (1 - distance/radius, radius 4 cells) of the nearest ghost, split by whether it is frightened. The old formula was ((1 + Dg*Pg*Wg)/(1 + Dp*Pp*Wp) - k*(1 + totalPellets*lives)/(1 + remainingPellets*initialLives))/remainingPellets: the product was 0 whenever a domain had no power pellet (almost always, the map has four), so one move could jump the ratio from 0.005 to 533, and dividing by the remaining pellets moved the scale from 1e-4 to 1e-2 over a level, which the calibration buckets could not follow. The new value keeps one scale and makes a lost life cost LIVES/initialLives = 0.30, above the whole control range (0.25) and equal to the whole level of progress (0.30). Effects: Pac-Man stops hugging the ghosts (average distance to the nearest ghost 3 -> 5 cells over the 25 s simulation) without eating fewer pellets; the trap still catches 20/20 and the circuit battery goes from 4/9 to 1/9 escapes. pacman-avoid still fails its playout: the one-step value prefers the escape by a wide margin (0.27 against 0.65 for the death) but the 24-200 extension RBFM does not propagate a death two plies down. Calibration must be rerun (CALIBRATION_VERSION 6).
    Benchmark
        src/tests/strategy/bench.js plays complete seeded games with the strategy in process (no worker, no real time), one context per game, and reports wins, cleared fraction, deaths, time and pellets per second. --walks is the search budget per decision (the worker spends a similar number of walks between two decisions), --weights overrides keys of config.strategy, --jobs runs the games on several threads and --json prints one line. Baseline with the normalised value (20 games, 6 walks, 90 s, classic map): 0 wins, 0.59 cleared on average, 0.6 deaths, 1.15 pellets/s, ~14 s of CPU per game. Coordinate sweep over SEARCH_VALUE_PROGRESS, SEARCH_VALUE_DANGER and SEARCH_VALUE_DANGER_RADIUS (10 games per point, 4 jobs, then 20 games for the finalists): PROGRESS 1 clears 0.59 against 0.51 with 0.3, and 0.15 (0.39), 1.5 (0.57) and 2 (0.53) are worse, so it is set to 1. DANGER 0.3 gives the same games as 0.15, RADIUS 3 ties with 4 (0.57 both) and RADIUS 6 is worse (0.42); with ~0.05 standard error those are not separable. SEARCH_VALUE_DANGER 5 gives 0 deaths but only 0.23 cleared. The remaining weights (CONTROL, PREY, LIVES) have not been swept.

AGENT NOTES:
Automated agents, please take the following points into account when working:
- Do not commit. Leave every change in the working tree, tell the developer what changed and which tests pass, and let them test it and commit. Run git commit only when the developer asks for a commit in that same message.
- Do not make changes while there are open questions or doubts on the table. Ask first and wait for the answer; never guess what the developer wants and implement the guess.
- Do not waste time checking every possible language. Test only English and one else and ensure that all languages have the same structure. To test this use automatic tools and include them in this project for the developers to use. Include them in the develop directory.
- After doing changes check if the request is here and ask to delete it and include it in the commit and the commit message.
- After doing any changes check if this file was changed by the human developer and include the change in the commit message.
- Limit Playwright tests to save tokens. Ask developer to either perform the tests by themself or let Copilot do them. If the developer chooses the first option, give them a list of the tests to do.
- All the useful tools used to make tests and propagate changes, like those to the language files, should be progressively added and updated in the develop directory for any developer to work, with comments detailing what are they used for.
- Do not automatically pick a TODO or SUGGESTIONS task and engage it. Do it just when a developer asks it to.
- Do not override changes to files on the work tree without asking what to do with the changes. 
- Add the relevant tests done to the program to the directory 'src/tests'.
- If a task is left mid-way, put it down here with a high priority (top in the list)
- If a task is done remove it here
